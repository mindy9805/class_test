# 補貨檢查

> 這是**挖空模板**。標 ★ 的地方要你自己填。
> 重點是「數字一定要從盤點資料抄，不能自己編」，而且每個數字都要能驗算。

## 什麼時候用

- 跑完 `npm run simulate`，要決定下一版策略每樣菜備幾份時
- 在瀏覽器玩完一天，想看「倉庫盤點」頁的結果該怎麼調整時

## 資料從哪裡來

在 `web-lab` 資料夾執行：

```text
npm run simulate -- plans/策略檔.json --json
```

每一天的 `inventory` 欄位，是那天每樣上架的菜的盤點：

| 欄位 | 意思 | 怎麼驗算 |
|---|---|---|
| `name` | 菜名 | — |
| `stocked` | 早上備了幾份 | 策略檔裡的 `qty` |
| `sold` | 賣出幾份 | 打烊報表 |
| `waste` | 報廢幾份 | 備貨 − 賣出 |
| `missed` | 賣完之後，還有幾位客人想買卻沒買到 | 客人卡片上「賣完了」的數量 |
| `status` | `ok` 正常、`out` 缺貨、`over` 報廢過多 | 規則書「倉庫盤點」 |
| `suggest` | 明天建議備幾份 | 賣出 ＋ 沒買到 |

## 步驟

1. 執行上面的指令，讀每一天的 `inventory`
2. 先驗算：`waste` 有沒有等於 `stocked − sold`？對不上就停下來回報，**不要用錯的資料做建議**
3. 挑出 `status` 不是 `ok` 的菜
4. ★ 建議備貨量要不要再調整（例如：明天客人比較多的日子，要不要多備幾份？多備幾份？）：
   - 只針對 `status` 是 `out`（缺貨）或 `over`（報廢過多）、而且已通過「寫完檢查」資料驗證的菜提出調整建議；`ok` 的菜只註明「正常，不調整」，不提建議。
   - **基礎建議量**（依今天資料，規則書「倉庫盤點」）＝ 賣出 ＋ 賣完後沒買到。回報時一定寫出算式，例如「10 ＋ 3 ＝ 13」。
   - **隔日調整**要另外一行，標明「考慮隔日條件後的調整」，和基礎建議分開寫，不能混成一個數字。只有使用者提供了明天的需求證據（例如明天的預告、星等、宣傳費決定）才可以調整，並寫出證據和算式；沒有證據就不調整，也不自行加固定百分比（例如「多備 10%」）。
5. ★ 同一樣菜連續幾天都缺貨或報廢過多，要怎麼提醒：
   - 同一道菜在資料中**連續兩天**都缺貨或報廢過多（`status` 連續兩天不是 `ok`）：回報時加一行「⚠ 菜名 連續兩天缺貨／報廢過多，這是持續現象」，並列出各天的數字（備貨、賣出、報廢、沒買到、狀態），不要只寫結論。
   - 只有一天資料時，不推測多天趨勢，也不能寫「持續」。
6. 用下面的回報格式回報

## 回報格式

```text
策略檔：
驗算結果：通過 / 第 N 天的 ○○ 對不上（寫出哪個數字）
第 N 天：
  缺貨：菜名 備 … 賣 … 沒買到 … → 建議 …
  報廢過多：菜名 備 … 賣 … 報廢 … → 建議 …
★ 我想多看一個欄位：建議備貨成本（建議備貨量 × 單份成本，寫出算式，例如「13 份 × 35 元 ＝ 455 元」）。單份成本只能用規則書 `docs/RULES.md` 菜單表的「成本（元／份）」，不得自行估算。
下一版每天建議的備貨量：
```

## 寫完檢查

- [ ] 每一個數字都能在盤點資料裡找到
- [ ] ★ 我再加一條檢查：（以下全部通過，才能提出備貨建議）
  - [ ] 原始數字（備貨、賣出、報廢、沒買到）都來自使用者提供的盤點資料，或上面「資料從哪裡來」列出的指令；算出來的數字（基礎建議、隔日調整、建議備貨成本、總份數、總成本）每一個都列出算式
  - [ ] 每一格數字都是非負整數；賣出沒有超過備貨；報廢 ＝ 備貨 − 賣出
  - [ ] 狀態和「明天建議備貨」照規則書核對：賣完後有人沒買到是缺貨，報廢 5 份以上是報廢過多，其他是正常；明天建議備貨 ＝ 賣出 ＋ 賣完後沒買到
  - [ ] 資料缺漏或互相矛盾時，已指出是哪一天、哪樣菜、哪個欄位有問題，並且停止提出該筆資料的備貨建議
  - [ ] 要判斷下一版完整備貨能不能執行時，已檢查所有餐點的總份數（規則書上限 80 份、最多上架 4 樣）、總成本 ＋ 宣傳費是否不超過可用資金；缺少必要資料（其他菜的數字、宣傳費或現有資金）就寫「尚無法確認可執行性」，不把單一道菜的建議當成已驗證的完整策略

## 不准做的事

- 不准修改任何檔案（這個 Skill 只讀不寫，要改策略交給 result-review）
- 不准自己編數字，或用「大概」、「差不多」帶過
- ★ 我再加一條：
  - 只在對話中回報：不准新增任何檔案、不准操作遊戲畫面（瀏覽器、遊戲按鈕）
  - 不准自行編造規則書內容、成本數字或盤點資料；資料不足就說缺什麼，不要補
  - 不准把單一道菜的建議說成已驗證的完整策略
